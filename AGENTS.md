# Agent instructions

These rules apply to every coding agent working in this repository (Claude Code, Codex, Cursor, Copilot and others) and to people as well. `CLAUDE.md` imports this file.

Chatly is a macOS app built with Rust and Tauri 2. The UI in `ui/` is plain HTML, CSS and JavaScript with no npm. Rust commands run in `src-tauri/`. Read [CONTRIBUTING.md](CONTRIBUTING.md) before changing code, especially [Rules you must keep](CONTRIBUTING.md#rules-you-must-keep).

## Before every commit and push

Do all three steps, in order, every time:

1. **Add or update unit tests for the change.** Every new or changed function, rule, setting, parser, domain, command or fix gets a test in the `#[cfg(test)] mod tests` of the module it touches. A bug fix gets a test that fails without the fix. The only exception is a change with no effect on behavior (documentation, formatting); say so in the commit message.
2. **Run the checks** in `src-tauri/`:

   ```bash
   cargo fmt --all
   ```

   ```bash
   cargo clippy --locked --all-targets --all-features -- -D warnings
   ```

   ```bash
   cargo test --locked --all-features
   ```

3. **Commit and push only if all of them pass.** Never skip, `#[ignore]`, weaken or delete a test to get a change through.

## Git

- Never commit or push to `main`. Work on a branch named `feature/<name>`, `fix/<name>`, `docs/<name>`, `refactor/<name>` or `security/<name>`.
- Commit messages are `<type>: <what changed>`, with type `feat`, `fix`, `docs`, `refactor`, `test`, `security` or `chore`.
- Changes reach `main` only through a pull request that uses the template and passes CI.
- Commit or push only when the person you're working for asks you to.

## Code

- **No comments** in code or configuration: Rust, JavaScript, CSS, HTML, TOML, YAML, shell or Python. Put the reasoning in CONTRIBUTING.md (a rule or a recipe) or in the pull request description. The generated files in `src-tauri/permissions/autogenerated/` keep the header Tauri writes.
- Keep the security rules. Some are enforced by tests: `every_command_is_declared_in_all_three_places`, `only_the_local_shell_can_call_rust` and `content_script_lists_the_same_domains`. If one fails, fix the code, not the test.
- Don't add a dependency without a reason in the pull request. After any dependency change, regenerate `THIRD_PARTY_LICENSES.md` with `python3 ../scripts/third_party_licenses.py`.
- Update `README.md` for anything a user can see, and `CHANGELOG.md` under "Unreleased".

## Safety on a developer's Mac

- `cargo run` and the self-test use the real data folder, `~/Library/Application Support/com.chatly.desktop/`. Never read, move, change or delete `vault.json` there unless the person asks. The self-test refuses to run while a vault exists: don't work around that.
- Never print or log passwords, keys, or cookie names and values.
- Build anything you hand to someone else only with `scripts/build-release.sh`.
